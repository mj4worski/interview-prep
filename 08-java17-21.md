# Java 17 i 21 — tylko to, co wychodzi na rozmowie

Masz 11 lat. Nie recytuj JEP-ów. Pokaż, kiedy byś tego użył w Springu.

## Java 17 (LTS) — must

### Record

Niemutowalny nośnik danych. `equals`/`hashCode`/`toString` za darmo.

```java
public record Money(long cents, String currency) {
    public Money {
        if (cents < 0) throw new IllegalArgumentException("cents");
        currency = currency.toUpperCase();
    }
}
```

Kiedy: DTO, event Kafka, wartość w domenie. Nie: encja JPA (Hibernate chce no-arg + mutowalne pola; da się, ból).

### Sealed + pattern matching switch

Zamknięta hierarchia zamiast otwartego `interface` + 15 implementacji.

```java
sealed interface PaymentResult permits Paid, Failed, Pending {}
record Paid(String txId) implements PaymentResult {}
record Failed(String reason) implements PaymentResult {}
record Pending(String txId) implements PaymentResult {}

static String msg(PaymentResult r) {
    return switch (r) {
        case Paid(var id) -> "ok " + id;
        case Failed(var reason) -> "fail " + reason;
        case Pending(var id) -> "wait " + id;
    };
}
```

Kompilator wymusza kompletność. To argument za sealed: nowy wariant nie przejdzie cicho.

### Text blocks

JSON/SQL w testach i skryptach. `"""..."""`. Nie do budowania SQL z user input (nadal injection).

### Switch expressions

`switch` jako wyrażenie, `yield` w bloku, no fall-through przy `->`.

### `var` + diamond

Lokalnie OK gdy typ widać z prawej. Nie w API publicznym. Nie `var x = null`.

### HttpClient (11+, ale pytają przy 17)

Wbudowany, async. W Springu i tak WebClient/RestClient. Wiedz, że jest.

## Java 21 (LTS) — must

### Virtual threads

Lekki wątek na carrierze. Model: **request = wątek** znowu ma sens przy IO.

Tak: dużo równoległego IO (HTTP out, JDBC, Kafka sync consumer), Tomcat z virtual na 21.

Nie: ciężki CPU (nie przyspieszysz), pinowanie (`synchronized` długo na native, JNI). Pinned carrier = uciekła równoległość.

Pula: `Executors.newVirtualThreadPerTaskExecutor()`. Nie kopiuj `core=200` z platform threads.

Ze Spring Boot 3.2+: `spring.threads.virtual.enabled=true`. Na rozmowie: „IO-bound serwis tak; najpierw zmierz, pinning i ThreadLocal w bibliotekach mogą boleć.”

ThreadLocal: działa, ale przy milionie VT jest drożej. W 21+ jest też scoped value (wspomnij, nie implementuj).

### Sequenced collections

`getFirst()` / `getLast()` / `reversed()` na `List`, `LinkedHashMap`. Drobiazg, czasem jako ciekawostka.

### Record patterns / pattern matching dojrzalsze

Rozpakowujesz record w `instanceof` i `switch`. Ten sam motyw co wyżej.

### Structured concurrency (preview w 21)

„Uruchom 3 IO, anuluj resztę jak jedno padnie.” Preview — powiedz że znasz problem (leak tasków w `invokeAll`), nie koduj API z głowy.

## Co zostaje z Javy 8–11, bo i tak pytają

- `Optional` tylko return, `orElseGet`
- Stream: czytelność > spryt; `parallelStream` nie default
- `CompletableFuture` vs virtual thread: VT prostszy do sekwencyjnego IO; CF gdy składasz wiele async bez blokowania
- `HttpClient`, `var`, factory `List.of` (immutable, nie akceptuje null)

## Grill

**Record vs Lombok `@Value`?**
Record to język, kanoniczny konstruktor, deconstruction. Lombok to generowanie. W nowym kodzie 17+ record na DTO.

**Czemu sealed?**
Jawny zbiór wariantów + wyczerpujący switch. Lepsze niż runtime `if-else` i otwarty inheritance.

**Virtual threads zamiast WebFlux?**
Często tak dla zespołu imperatywnego. WebFlux zostaje gdy już macie reactive stack / streaming backpressure. Nie przepisuj wszystkiego w tydzień.

**Czy record jako klucz w HashMap?**
Tak, jeśli składowe niemutowalne i dobrze zdefiniowane. To jedna z zalet.
